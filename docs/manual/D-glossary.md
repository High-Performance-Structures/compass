# Appendix D. Glossary

> Generated by `scripts/manual/generate-appendices.ts` from the source tree. Do not edit by hand; rerun `bun scripts/manual/build.mjs`.

## D.1 Terms

| Term | Meaning |
|---|---|
| **Action context** | The shared resolver in src/lib/server/action-context.ts (userContext, orgContext, projectContext) that every server action and API route starts from: user, active organization, database, feature permission and demo read-only check in one place. |
| **ActionResult** | The return shape of every server action: { success: true, data? } or { success: false, error } (src/lib/action-result.ts). Actions return failures rather than throwing. |
| **Activity** | The project timeline of who did what (activity_events plus record-specific history tables). Outside email, approvals and status changes are logged here. |
| **Assembly** | A reusable group of estimate lines (for example a wall type) that can be priced as one unit, exported to a phase estimate, or copied into another job. |
| **Audience** | Who a project surface is for: staff (the company's own users), owners (clients) or vendors (subcontractors and suppliers). Owners and vendors see only records shared with their audience. |
| **Baseline (architecture)** | src/lib/__tests__/architecture-baseline.json: the frozen list of existing violations of the architecture standard. Counts may only fall. |
| **Baseline (schedule)** | A saved copy of a schedule's dates (schedule_baselines) used to measure slippage. |
| **Bridge (accounting)** | The on-premises agent that reads from and writes to the desktop accounting system, talking to Compass through signed HTTPS requests. Compass never connects to the accounting database directly. |
| **Change order (CO)** | A priced change to an accepted contract (project_change_orders). Approval revises the contract budget. |
| **Company values board** | A recognition board where staff send cards tied to company values. Its name and values are configurable per company in Settings. Code and tables use the {values} placeholder prefix in this manual. |
| **Cost code** | A job-cost classification from the accounting system (sage_cost_codes, project_field_cost_codes), used on estimate lines, POs, time and budgets. |
| **D1** | Cloudflare's serverless SQLite database. Compass's single relational store (binding DB). |
| **Daily log** | A field report for one project and day: work done, crew, weather, photos, and items that can become to-dos. |
| **Demo company** | A separate deployment (wrangler env demo) with its own database and no scheduled jobs or outside integrations, seeded with the neutral example company Summit Ridge Builders. There is also a read-only demo user and organization in the main deployment. |
| **Department** | A configurable division of work (for example construction, design, home services, product sales), each with its own job-number prefix and workflow. Departments can be switched on or off per company. |
| **Domain module** | A folder under src/lib/domain/<module>/ that owns a set of tables: store.ts (all writes), rules.ts (pure logic), access.ts (who may). |
| **Drizzle** | The TypeScript ORM used for the schema (src/db/schema*.ts) and queries. |
| **Estimate** | A priced scope for a project (project_estimates and lines). Several estimates may exist per job; acceptance turns one into contract value. |
| **Family (project family)** | A set of linked jobs across departments, for example a design job and the construction job it leads to (project_families, project_family_phases). |
| **Feature permission** | A named capability (for example project-photos) with read/create/update/delete actions, checked by canFeature in src/lib/permission-enforcement.ts. Role defaults can be overridden per role, team or user. |
| **G702 / G703** | The industry-standard application-for-payment summary and continuation-sheet formats that pay applications follow. |
| **Job number** | The human-facing project number. Format and prefixes are configurable per company and department; numbers are reserved and never reused (project_number_reservations, project_number_retirements). |
| **Job status** | A project's position in its pipeline (lead, estimating, contracted, in progress, closed and so on). Labels are configurable per company (project_job_statuses). |
| **OpenNext** | The adapter that builds the Next.js app into a Cloudflare Worker (@opennextjs/cloudflare). |
| **Owner** | The client who commissions the work. Owners sign in to a limited, permission-scoped view of their own projects. |
| **Paper trail** | The background job that writes a Drive copy of each changed record (estimates, change orders, logs and so on) after a quiet period, so the project's Drive folder holds a durable record. |
| **Pay application (pay app)** | A progress-billing request in G702/G703 form. Approved for billing, it becomes visible to the owner and is matched to an accounting invoice number. |
| **Phase** | A grouping of estimate or schedule work (for example a design phase) that can be proposed, approved and billed separately. |
| **Print Preview** | The standard printable view of every document (estimate, change order, pay app, log), rendered from the same data the screen uses. |
| **Product sales / online ordering module** | An optional module for selling catalog products: versioned catalogs and prices, customer orders, rentals, and public order pages. Code and tables use the {sales} placeholder prefix in this manual. |
| **Purchase order (PO)** | A commitment to a vendor or supplier for a scope or materials, created from an awarded bid or directly (project_operations of kind purchase order plus project_purchase_order_lines). |
| **Ratchet** | A CI check that freezes today's count of a violation and fails if it grows (or shrinks without the baseline being updated). |
| **RFI** | Request for information: a question to the design team or a vendor, tracked with replies (project_rfis). |
| **RFQ** | Request for quote sent to vendors for a scope; replies become bids that can be compared and awarded. |
| **Selection** | An owner choice of finish or product (project_selection_decisions, project_finish_selections), with requests, decisions and links to procurement. |
| **Server action** | A Next.js function in src/app/actions/ marked "use server" that the browser calls directly. All mutations go through one. |
| **Snapshot** | A column or row that deliberately freezes a value as it was when a document was signed, sent or approved. Named *_snapshot or commented // snapshot:. |
| **Store (store.ts)** | The only file allowed to insert, update or delete a domain's tables (one writer per table). |
| **Summit Ridge Builders** | The neutral example company used in the demo deployment and in this manual's examples. |
| **To-do** | An assignable task on a project (project_operations of kind to-do), with events, reminders and links to daily logs. Finished items are ticked by people, never automatically. |
| **Tracked email** | Outside email sent through sendTrackedEmail with a reply address tied to the record, so replies are imported back to the same thread, notification and Activity. |
| **Vendor** | A subcontractor or supplier. Vendors can be invited to projects and see only what is shared with the vendor audience (RFQs, POs, documents, schedule items). |
| **WorkOS** | The hosted identity provider used for sign-in, SSO and invitations (pluggable behind src/lib/auth.ts). |
| **Workspace** | A permission-scoped area of the app: a project's staff workspace, the owner portal, the vendor portal, internal (non-project) workspaces such as the office duty log. |
